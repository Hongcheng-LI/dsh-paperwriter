# Technical returns and resubmission files

Use for an editorial-office unsubmission or technical return concerning article type, word limits, file separation or missing submission components. This is a submission-format task unless the author also requests scientific revision. Prepare the concrete local files within the existing authorization; uploading or submitting requires explicit authorization.

## Resolve the actual requirement

Read the author's current submission folder, cover letter and supplied editorial message. Record which requirement applies to which article type and file. Treat a specific editorial instruction for this manuscript as the operative instruction for its stated scope; distinguish it from generic publisher advice and example-paper habits. Follow higher-level constraints and report any unresolved conflict rather than silently substituting one source. A blocked journal page does not prevent implementing a clear supplied editorial requirement.

A message may quote several article-type limits or contradictory automated notices. Do not combine them into a single target or change article type merely to fit a warning. Establish the intended type from the current manuscript and cover letter, then inspect available submission metadata. If the portal setting is unavailable, state that it remains unverified and tell the author the specific setting to check.

## Count before cutting

- Measure the actual latest manuscript with the target system's documented method when accessible, or a documented local method such as the word processor's word-count API. A rough whitespace count is not equivalent to the submission system's count.
- Record the exact range and inclusion rules: title/front matter, abstract, keywords, headings, in-text citations, Experimental, acknowledgements/declarations, captions, table text and references. Native equations and tracked changes can affect what plain-text extraction sees.
- Locate actual section boundaries rather than the first occurrence of a word such as “references” in front-matter metadata. Use paragraph/heading identity or a bounded range and inspect the resulting text. Report separate counts for competing plausible rules when that distinction changes the conclusion.
- Apply the limit for the intended article type, including an Experimental-section allowance only when supported by the supplied instruction. Do not hard-code a journal's present numeric limit into the reusable skill.
- If the manuscript is already within the applicable limit, address the file arrangement or article-type mismatch without removing necessary methods. If shortening is needed, preserve endpoints, controls, replicates and conditions in the text or a correctly cited SI location.
- Put the measured count and scope in the manuscript or cover letter when useful or requested; derive them from the same final file. Recount after a substantive change. Do not claim that a local count proves what the portal counted.

## Separate main-text figures and tables

Create a file-role manifest before moving content: main manuscript, each main figure/table, SI, graphical abstract and cover letter. Separate only the items covered by the instruction. An author may already have moved some figures to SI or combined several data tables; preserve that allocation unless instructed otherwise.

For one-file-per-item requirements, provide exactly one upload copy of each numbered main figure or table in an accepted format. Follow the instruction's caption arrangement: a standalone DOCX may hold a figure and editable caption when that format and arrangement are accepted; otherwise supply the requested image format and corresponding caption file. Keep tables editable where required. Do not duplicate the same figure as DOCX, TIFF and PDF in the upload directory merely to offer options. Keep QA renders and editable alternatives outside that directory.

Remove the actual figure/table objects, related captions/notes and obsolete page breaks from the clean main document while retaining its in-text callouts. Preserve equations and other inline scientific content. With DOCX tooling, check for leftover floating drawings and unused image relationships as well as inline shapes. Clean tracked changes only when the intended final content is established; accepting formatting/equation insertion markers must not erase equation content.

Preserve original image bytes when a direct extraction is sufficient. Do not redraw scientific structures or inflate nominal DPI as a substitute for image detail. If reporting effective resolution, derive it from the pixel dimensions and intended display size. Check figure labels, caption identifiers, table headers/units and notes in the standalone output.

## Reconcile and hand off

Check every cited figure/table against the actual current main and SI files. A combined supplemental table can invalidate old separate-table citations; moving a multipanel figure requires checking both its figure number and panel suffixes. Inspect the SI contents list and actual captions separately.

Compare all table cells, row/column counts, notes and image counts/hashes where applicable; avoid pairwise comparisons that silently ignore extra or missing rows. Preserve titles, author details, scientific values and source files. Check semantic formatting and native equations separately from text equality.

Update the resubmission cover letter to describe the technical corrections and measured scope without inventing a manuscript ID or new scientific findings. Ensure confidence qualifiers agree with the manuscript. Record evidence changes separately from administrative edits.

Render the final manuscript, standalone figures/tables, SI and cover letter, then inspect their pages. Verify that the upload directory contains only the intended files and no duplicate artwork or QA intermediates. A ZIP for convenience should contain that exact file set; explain that the author should extract and upload files individually if that is what the portal requires.

Report the resolved technical issues, actual counts and file roles, plus any portal settings that still need checking. Distinguish a prepared local package from an uploaded or submitted one, and distinguish format verification from scientific revalidation.
