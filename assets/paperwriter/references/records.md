# Record conventions

UTF-8 for Markdown/JSON/JSONL; UTF-8 with BOM for CSV. Relative project paths for portability. Stable IDs by type (SRC, CLM, ISSUE, OUT); never recycle IDs. A source revision retains identity with a revision/hash record. Distinct files retain distinct IDs until manually resolved, even if identical; deduplicate analysis through a recorded canonical relationship.

Corpus JSONL: one object per unit, keys source_id, unit_id, parent_id, unit_type (article/section/paragraph/sentence/caption/table), heading, position, locator, raw_text, normalized_text, function_tags, extraction_quality, scientific_verification, reuse_policy. function_tags is an array. reuse_policy = rhetorical_analysis_only. Paragraph parents must exist; no orphan sentences.

Use assets/templates for claims.csv, citation_evidence.csv, output_links.csv and issues.csv. Their headers define minimum interfaces, not a required scientific ontology.
- claims: observations, interpretations, hypotheses, methods, background remain distinguishable.
- citation_evidence: source identity verification and passage support verification are separate.
- output_links: each claim connects to identifiable manuscript section/passage, figure, table, caption or SI.
- issues: unresolved facts and decisions link to affected claims.

Inventories are immutable timestamped snapshots generated by the script, not claims of scientific review. Reuse previous source IDs by relative path, flag content changes and removals. A rename is provisionally a removed source plus an added one; resolve manually without deleting history.

Gate records: author message reference/date, accepted artifact, artifact version/hash and any explicit reservations. Dates alone are not enough for version control.

No universal requirement that every claim has a p-value, every paper has Conclusions, or every corpus sentence passes a scientific audit.
